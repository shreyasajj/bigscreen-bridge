## Implemented

- Local session D-Bus JSON endpoint with request IDs, acknowledgements, schema
  validation, bounded pages, replay handling and single-instance UI lease.
- Opaque source-qualified automation IDs. TVHeadend IDs use the persisted source
  namespace. M3U identities survive playlist reordering and token rotation;
  ambiguous entries are excluded rather than assigned positional automation IDs.
- Current/next EPG, actual QtMultimedia playback state, and play/pause/stop routed
  through the existing player and timeshift recorder. Catalogue readiness is
  separate from QML readiness, so cold-start selection can wait for channels.
- Native HA active-app and dedicated Flimmer players, dynamic capability flags,
  typed `flimmer_channel` playback and paginated channel browsing.
- Flatpak bus permission, user-only SDK build/install helper, deployment script,
  real-TV smoke test and a synthetic IPTV fixture with its own settings/data.

## Verified on the TV

18 Qt test suites pass in the installed KDE SDK 6.11, including parser, guide,
cache, source, backend, identity and native control protocol tests. The root
bridge/HA suite has 75 passing tests; Ruff passes. Flimmer clang-format, gersemi,
REUSE and whitespace checks pass. clang-tidy is not available in the SDK and was
not run locally.

Using the actual installed Flatpak, real Plasma Wayland window, authenticated
bridge and local HTTP source, the fixture verified:

- Endpoint readiness, duplicate launch reuse and rejection of arbitrary URLs.
- Bridge cold launch of the normal profile, followed by restoring Couchside focus.
- 55 channel identities, two browse pages without duplicate entries.
- Real XMLTV current and next programme metadata.
- Channel selection acknowledged by Main.qml.
- Actual MPEG-TS playback, pause and timeshift resume.

The captured TV image `artifacts/flimmer-playback-tv.png` was inspected: it shows
rendered colour bars, the selected channel, current/next guide entries and the
Flimmer timeshift indicator after resume. The fixture restores the normal profile;
it never adds test channels to the user's source list. Private source settings and
EPG data were backed up under `~/.cache/bigscreen-backups/flimmer-phase7-*`.

## Limits

The normal Stalker source returned no channels during a 30-second check. No claim
is made that this external provider plays. The synthetic MPEG-TS feed is local,
silent and generated by ffmpeg, so it verifies the application path rather than
provider availability. TVHeadend source behavior is covered by backend/source
unit tests; no live TVHeadend server was used in this phase.

Provider logos are omitted until a safe image proxy can serve image bytes without
exposing credentials embedded in URLs. Live broadcast schedule times are not
reported as a seekable playback position/duration. Volume and seek stay disabled.

The HA integration was tested against installed HA Python APIs, but is not yet
installed into the user's HA instance; configuration-folder access remains
unavailable. MQTT transport and VacuumTube runtime control remain later work.
